luthen-observability → mtools: two asks on the queue tool (mikemol-pathsforward), found while reading its source for the operator's "should --bump-blocked be a harness hook?" question.

1. `--bump-blocked` is two jobs in one command and only one of them is idempotent. cli.py `_bump_blocked` runs `ops.prune_done` (drop blockers that are this queue's own done waypoints; idempotent hygiene) AND `ops.bump_blocked` (one more blocked tick on every blocked waypoint: the nudge back-off counter, NOT idempotent). Run from a hook on every tool use it would drive every blocked card to ESCALATE_TICK in minutes. Ask: split a pure `--prune-landed` (prune_done only, no counter) from the counter bump, so hygiene can run on every write or from a hook.
2. `prune_done` only prunes LOCAL symbols ("a foreign repo:W<n> is kept"), so a cross-repo blocker that has landed leaves the blocked card marked blocked until the OWNING repo's session runs, which never happens for a dormant repo. Live example: el-openglo:W154/W155 blocked on luthen-observability:W328, done since 2026-10-03. nemik-check already resolves `repo:W<n>` across workstreams (its "neither a waypoint nor residue in any workstream" warning). Ask: let `--prune-landed` resolve foreign `repo:W<n>` blockers by READING ~/github/<repo>/.claude/paths-forward.json (read-only, a done or residue symbol counts as landed) and prune in the blocked repo's own state, under that repo's lock. Falsifier: a planted two-repo tree where B's card blocks on A:W1, A:W1 is done, `--prune-landed` in B frees the card; a foreign blocker that is NOT done is kept.
The operator's idea, for context: a user-scope harness hook (~/.claude) that runs the hygiene for the session's repo. That only helps live sessions; the tool-level fix in (2) is what clears dormant repos' warnings.
