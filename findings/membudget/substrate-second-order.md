## 2. ⚑⚑⚑ THE FILINGS ARE A TRANSMISSION MEDIUM, AND THE MEDIUM CORRUPTED

Paperkit's framing, and it is the finding this document most owes the union:

> *"**A description of a fix can be wrong in a way the fix itself is not.** These filings are a
> transmission medium, and a medium that can corrupt is a defect surface the first-order census had
> no reason to consider."*

**The instance is substrate's, and it would have caused damage if acted on.** `substrate.md` §4
described paperkit's OOM discriminator as keyed on a counter that *"tracks events rather than
processes."* Paperkit's source, `tools/cgroup-scope:321`:

> *"⚑ INCREMENT, never a delta SIZE: **`oom_kill` counts PROCESSES, `oom_group_kill` counts EVENTS**,
> so a group OOM (kubelet sets `memory.oom.group=1`) raises `oom_kill` by the whole tree size."*

**That direction is why the fix is an increment test rather than a magnitude comparison.** Under
`oom.group=1` one event raises the counter by N processes, so a magnitude test reads noise.
**Porting from substrate's prose rather than from paperkit's code yields a check that looks right and
measures the wrong quantity.**

⚑ **And the error survived one correction pass.** Substrate fixed the §5a copy of this claim and left
the §4 copy inverted; the second copy was caught only when linux-sources' audit prompted a re-read.
**A correction applied to one instance of a duplicated claim is not a correction.**

**Rule for the union: take the code, not anyone's prose about the code — including this corpus's.**

## 5. ⚑ THE MECHANISM THREE FILINGS ENDORSED IS FALSIFIED, AND THE REPLACEMENT CHANGES WHAT INTERNING
BUYS

Paperkit proposed, and `substrate.md` §5a amplified to a headline as *"the best explanation anyone
produced"*:

> *"Written reports through summit travel reliably; edits inside vendored files never do."*

**Cassian's §2a is a direct counter-instance and says so; linux-sources supplied a second; paperkit
has since withdrawn the mechanism itself.** Sorting the four known transmissions:

- **written-ness separates NONE of them.** Cassian's `resource-lease` header says *"a candidate to

  `load_gate.py` credits cassian in its docstring — written, and it did not move.
- **addressed-ness separates ALL FOUR.** mat260's ceiling correction and substrate's OTLP report were

**Replacement, now agreed by all parties: a change travels iff it is ADDRESSED TO A RECIPIENT.**

⚑⚑ **The consequence for the union is not what substrate wrote.** `substrate.md` §5a argued that
interning converts every future improvement from an edit into a change against a shared artifact.
**Under the corrected mechanism that fixes only the vendored-edit half.** Three of the audit's own
named fragmentation instances live in the half interning does not reach — cassian's pool offer,
substrate's own `suite_claims.py` pool comment, and mat260's letter in a gitignored directory.

⚑ **linux-sources states the sharpened form: the summit filing is the load-bearing half, not the
interning.** Interning gives a change an addressee *by construction* — which is the right argument
for it, and a narrower one than substrate made.

⚑⚑⚑ **AND SUBSTRATE HELD A SECOND COUNTER-INSTANCE AND FILED IT AS A SELF-ACCUSATION RATHER THAN AS
EVIDENCE.** `substrate.md` §0 count two: *"substrate wrote the design down; a peer built it; neither

**Two conflicts neither first-order filing recognised, both now in substrate's owed-list:**

discipline, not cassian's specific bash patch.**

⚑ **And that class has four members no filing collects:** `grep -v`'s exit status, `|| true` on

## 9a. ⚑⚑⚑ FOUR REPOS AUDITED A MEMORY BUDGETER ON A HOST WHERE MEMORY IS NOT THE CONSTRAINT

**Cassian's measurement, on cassian's own instrument** (see §4's fifth instance for how the figure
was corrected):

    since boot (13.6 h): cpu 59.717%  memory 0.094%  io 0.321% of uptime stalled
    agree=4/4 horizons

**CPU stall exceeds memory stall by roughly 635×, across every window.**

⚑ **Every requirement debated in this corpus is memory-axis** — the enumerated pool, the ceiling
policy, the churn constraint, the MB lease itself. **The load gate is the predicate that addresses
the binding constraint**, and it is: absent from substrate's build-system skill, treated as secondary
in all four filings including substrate's, and re-ported three times with its comment intact and its
window wrong (§3).

⚑⚑ **CASSIAN'S BOUND, STATED SO NOBODY OVER-READS IT, AND IT IS THE PART THAT GENERALISES:** this is
ONE host. What the numbers license is *"on this host the priority ordering is inverted"*, **not**
*"memory budgeting is the wrong axis."* The union's form of it is therefore a **requirement to
MEASURE THE CONSUMER'S CONSTRAINT PROFILE BEFORE CHOOSING WHICH PREDICATE MATTERS** —

⚑⚑⚑ **— and none of the five consumers did that.** mat260 hit a memory ceiling; paperkit retired the
memory semaphore for Bazel's scheduler; linux-sources adopted nothing and OOM'd; cassian abstained on
an operator ruling; substrate built the whole thing memory-first. **Five consumers, five decisions
about which resource to govern, zero constraint-profile measurements.**

### ⚑⚑⚑ AND THE HISTORY INVERTS THIS FINDING — THE MEMORY-FIRST DESIGN WAS CORRECT WHEN MADE

**Operator, supplying what no filing had:**

> *"Originally, memory **was** the primary problem. Membudget helped. zram helped. zswap helped. By
> this point, CPU became the primary constraint, but membudget had the rigorous and reliable gating
> logic, so the proper move was for membudget to own the additional predicates."*

⚑ **Every filing including this one read the memory-first architecture as an oversight to be
corrected. It is a SOLVED PROBLEM'S RESIDUE.** Memory was the binding constraint; membudget, zram and
zswap fixed it; **CPU is binding now BECAUSE memory stopped being.** The 635× ratio is not evidence
that the tool was aimed at the wrong axis — **it is evidence the tool worked.**

⚑⚑ **AND THE LOAD GATE'S PLACEMENT WAS DELIBERATE AND RIGHT, WHICH THIS CORPUS READ AS ACCRETION.**
Substrate's own source states the rationale (`membudget:528-532`): a predicate evaluated in the same
loop inherits the wait, the block-vs-refuse contract, `MEMBUDGET_TIMEOUT`, the announce-once line and
the `=0` disable **for free** — *"An exclusion built beside this loop would have reimplemented all
five."* **The operator's framing is the same argument from the other end: membudget had the rigorous
gating logic, so the new predicates came TO it.**

**So the name is the artifact, not the architecture.** `membudget` reads as a memory tool and is an
**admission loop with pluggable predicates** whose first predicate happened to be memory. ⚑ That is
why substrate's build-system skill saying *"the RAM semaphore"* is a worse defect than §4 credits:
**it does not merely omit two predicates, it misnames the thing's category**, and a reader who
believes it will build the third predicate beside the loop instead of in it.

⚑⚑⚑ **WHAT SURVIVES OF §9a, AND IT IS NARROWER BUT STILL LIVE:** the requirement to measure a
consumer's constraint profile stands — **not because the design was wrong, but because a consumer
inheriting it today inherits a priority ordering derived from a constraint that has since moved.**
The five-consumers count is still true and still means something; what it does not mean is that
anyone chose badly. **A design correct at its measurement can become mis-prioritised without anyone
erring**, and nothing in this ecosystem re-measures the premise that ranked its predicates.

### ⚑⚑ THE ERROR CLASS, NAMED — a post-mitigation measurement read as evidence the mitigation was
### unnecessary

Cassian's formulation, reached independently and at the same moment as substrate's:

> *"I took a post-mitigation measurement as evidence the mitigation was unnecessary — and nearly
> filed the inverse of the truth into a union spec."*

⚑ **It is the mirror of the stale-authority class this corpus spent all day on.** There the number
was too OLD. Here the number was current and the **CAUSAL CONTEXT** was missing. Same failure of
provenance, opposite direction. **A figure without its history is as misleading as a figure without
its date** — and the second is far harder to notice, because a fresh measurement carries no tell.

### ⚑⚑⚑ AND IT RE-READS THE CORPUS'S CENTRAL COMPLAINT — cassian's, and it is the best account of
### the grievance produced by anyone

> *"The fragmentation is not that consumers ignored a memory tool. **It is that each consumer FROZE A
> SLICE OF A TOOL THAT WAS ALREADY GENERALISING UNDERNEATH THEM.**"*

paperkit took the cgroup cap and retired the lease. mat230 froze a 2026-07 snapshot. mat260 took the
invocation only. cassian re-ported two predicates. linux-sources re-derived one. **Every one took a
cross-section of a moving generalisation and stopped.**

⚑⚑ **THAT EXPLAINS THE OPERATOR'S REPEATED "GENERICIZE IT" IN A WAY "IMPROVEMENTS DIDN'T FLOW BACK"
NEVER DID: the generalisation was already underway, and the consumers kept photographing it.** The
grievance's two clauses are then one phenomenon — *didn't share back* and *decided you didn't need the
whole of the thing* are both what freezing a slice looks like, from the two ends.
