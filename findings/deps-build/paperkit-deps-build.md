## PK-02 Dependency discovery — and the class no manifest names

**Explicit:** import scanning exists (`tools/closure.py`, `tools/sites.py`, `def_sites.py`), and a
`bib_repo` module extension reads each project's `paper.toml` at fetch time and **watches** it.

⚑ **Implicit dependencies are the interesting half, and paperkit has them by design.** A check verb
is a *project-declared shell string* (`[checks.<verb>] cmd=`), so **paperkit runs arbitrary `PATH`
programs**. Four are named in `tools/toolchain_status.sh`: `pandoc`, `verapdf`, `lualatex`,
`soffice`. Seven check verbs are declared across projects (`claim`, `definition`, `fig`, `fresh`,
`load`, `premise`, `ref`), and a verb's `cmd` can name anything.

**Other implicit deps, measured:** a k3s BuildBuddy at `:31985`/`:31080`/`:31464`; an env var
`PAPERKIT_BES` read from a **gitignored** `.githooks/local.env`; the `mise`-managed interpreter.

## PK-03 Acquisition — and what a cold machine does

Bazel fetches everything in `MODULE.bazel` (registry + two `pip.parse` hubs, hash-pinned).
⚑ **The engine itself is acquired as a WHEEL, built in-tree** (`tools/wheel.py`, `//paperkit:wheel`)
and **extracted into a per-cell venv**. Extraction is a *complete* install only because the engine
declares `dependencies = []`; with real deps this technique would silently skip resolution.
**This is staged, not committed** — see PK-10.

**Cold machine gap, stated as a finding:** the four `PATH` toolchain programs are **not acquired by
the build**. A cold machine without `pandoc` produces `STABLE_TOOLCHAIN_PANDOC absent` and the
affected checks degrade rather than the build failing.

## PK-04 Hermeticity — what the build reaches without declaring

⚑⚑ **MEASURED, and it is the defect that drove the staged work: the execroot's `paperkit/` is a
SYMLINK TO THE LIVE CHECKOUT.** So `PYTHONPATH="$PWD"` and a relative `.pth` both read **unstaged
sources** — a sandbox escape that passes green. **CITATION**, `.bazelrc` (RBE rationale, written for
a different purpose):

> *"unlike Bazel's local sandbox, which symlinks first-party packages straight back to the working
> tree (measured this session: `$EXECROOT/paperkit` is a symlink to the live checkout, which is how
> a check could read UNSTAGED sources and pass)."*

⚑ **A gate that passes by not running — found, twice, today:**

1. **The toolchain stamp is blind to a replacement.** Three of four keys are `--version` **banners**;
   only the veraPDF *jar* is content-hashed. ⟨P,F,δ⟩ with a shim whose banner is pinned:
   `STABLE_TOOLCHAIN_PANDOC pandoc 3.1.11.1` **identical** across `sha256 6dd4b433… → d7c283e5…`.
   **A toolchain-tier verdict survives a total replacement of the tool that proved it.**
2. **73 hand-declared `reads = {…}` fields across 16 `.bib` files.** A closure wrong toward *too
   small* is a stale green, and only a hermetic tier converts it to an error — which is why PK-03's
   wheel work gates this one.

## PK-05 Build design — three tiers, records-as-deps, and one measured number

**Tiers** (`tools/verb.bzl`): `sandbox` (hermetic, cached) · `local` (host, **uncached** —
`no-cache`+`no-remote`) · `toolchain` (host, cached, `ctx.info_file`-stamped).

⚑ **`execution_requirements` is fingerprinted twice** in Bazel's `computeKey` (`getExecutionInfo` +
`getExecProperties`), so **a tier marker is part of action identity** — a `local`-tier and a
`sandbox`-tier action with identical argv and inputs are *different actions*. **TESTIMONY**
(linux-sources, read from Bazel 8.7.0 source); not re-derived here.

**Records-as-deps:** a child project's verdict is a **File**, therefore an action input, so Bazel's
action cache memoizes an unchanged child. That is the mechanism that makes cross-project delegation
cheap.

⚑ **Graph size, MEASURED from the live run: 126,657 actions configured.** `.bazelrc`'s heap ladder
records 125,471 (2026-08-27) then 152,367 (2026-08-31) and closes:

> **CITATION:** *"the ceiling tracks GRAPH SIZE and **nobody re-derived it when the graph moved**.
> The next arc that adds modules moves it again."*

The graph **shrank ~17%** against the last recorded figure, and the comment predicted growth. **A
ratchet that only clicks upward records a high-water mark, not a size.** Cause unmeasured — the
`--local_resources=memory=6248` budget may partition differently; attributing the delta would repeat
the inference being corrected.

**Remote:** BES only. `--config=mutant` is **one line** (`--experimental_use_hermetic_linux_sandbox`)
and pulls in neither cache nor executor. See PK-09.

## PK-06 Test design — a claim, and whether it is falsifiable

A **test is a claim in a `.bib`**. 49 warrants in `boundaries/warrants.bib`; 9 `.bib` files across
projects. A claim binds to a check verb, which produces a **verdict record**.

⚑⚑ **Falsifiability is mechanised, not assumed — this is paperkit's distinguishing answer to §Q-6.**
The gate runs a **mutation sweep**: each claim is re-evaluated against systematically mutated
definitions, and a claim whose verdict does not change under mutation is **indeterminate**, not
passing. **MEASURED from the live run: 8,114 distinct `Ζ·eval` cells.** A claim is graded on a
ladder (`broken −1 · vacuous 0 · indeterminate 1 · existence 2 · behavioral 3 · imported 4`), and
the sweep is what separates 1 from 3.

⚑ Every tool ships ⟨P, F, δ⟩ — minimal pass, minimal flag, minimum delta between them.

## PK-08 ⚑ What I re-derived — the highest-value item

- **A per-cell venv + wheel install** (`tools/wheel.py`, `tools/cell.bzl`) — built because
  `pk_cmd` runs *arbitrary user-authored shell strings* where no runfiles tree exists. ⚑ **A peer
  read this and correctly declined it**: `py_binary` is the stronger form where you have one, and
  wheel-extraction-as-install holds only under `dependencies = []`. **The re-derivation is real and
  the shared alternative did not cover my case** — that is the honest shape of this answer.
- **An action-idempotent scratch claim** — build to `.cellvenv.<pid>.tmp`, write a marker,
  `os.rename` to claim the shared name. ⚑ **This is a lease**, hand-rolled, and `membudget`'s
  `claim:<tag>` is the same primitive. I did not know that when I wrote it.
- **A liveness discipline in prose** (`dont-edit-during-build`: *"check `pgrep bazel` before ANY
  edit"*) where an instrument exists. ⚑ **It failed today, by its own author** — I edited
  `tools/wheel.py` 70 seconds into a live gate. *A rule obeyed by remembering is not a mechanism.*
- **A stale-pointer class**, twice: `.githooks/local.env` asserting *"BES (:1985) did NOT move;
  verified open"* while `:1985` measured **closed** — ⚑ a stale claim **carrying its own
  verification**, which is why it survived a reader applying *verify, don't trust*.

## PK-09 ⚑ What I declined, and one I did not know I was declining

- **`--remote_local_fallback` — I did NOT decline it, and that is the finding.** paperkit sets it on
  **both** remote configs (`.bazelrc:247`, `:283`). Per `§X` it is ruled out. It is also precisely
  what would prevent me noticing I am not on the sanctioned config — which I am not (PK-05).
- **Removing it is not one change.** ⚑ paperkit declares **zero `platform()` targets**, so
  `--config=remote` resolves against the default host platform. The fallback must come off **last**,
  after a platform is declared, or a red gate gets attributed to the wrong cause.
- **`membudget` — declined by deletion, with a reason, and the reason was wrong on one axis.**
  `95d12ad` (2026-06-27): *"Bazel IS the semaphore — per-machine, no cross-repo flock."* True for
  actions contending for **capacity**; silent on agents contending for the **tree**.
- **Fetch-time generation over generate-and-commit** — 117.5 MB of BUILD generated inside the build.
  ⚑ Cost measured on my own side: `Ζ·watch·closure` — the module extension's watch list named a
  **retired** file and missed two live ones, so editing a live generator input did not invalidate.
  A byte-comparison staleness gate has no watch list to get wrong.
